== Scope and evidence

This gap analysis is based on the supplied `ADJUSTMENT_ASYNC_MULTIPLAYER_API_FIRST.adoc`, `LOOPRD_GAME_PLAY_CONTRACT.adoc`, `END_TO_END_TEST_PLAN.adoc`, and the Life v0.5.79 source ZIP. The three supplied documents are proposed architecture and acceptance requirements, not proof of features deployed in Social, Atrium or DAPI. Only Life source was audited locally for this pass. All cross-repository capabilities require owner verification.

== Delivered in Life v0.5.80 (LIFE-ASYNC-01 partial)

* `LifeGame.load(snapshot, {advanceAI:false})` can restore a checkpoint without implicitly executing a Jones turn; default remains compatible with existing browser load behavior.
* `src/async-replay.js` provides an initial Node headless checkpoint adapter, deterministic key-order canonical JSON, SHA-256 comparison digest, and explicit RNG-state extraction.
* `tests/async-replay-080.test.cjs` checks repeatable checkpoint reconstruction and canonical hash equivalence.
* Existing Classic/Modern/offline gameplay is not migrated to `/play` in this pass.

IMPORTANT: The adapter is *not* yet a pinned rules artifact or a secure player-command evaluator. The canonicalization strategy and complete data schema still require versioned approval; no network endpoint, SQL migration, ticket verifier, deadline service or Social integration is claimed.

== Shared contract actions and dependencies

. Life: publish real OpenAPI `GET /play/info`, `POST /play`, schemas for `create`, `join`, `list_matches`, `get`, `resume`, `legal_actions`, `act`, `end_turn`, `history`, and `status`/`resign` as decided. Until deployed, advertise no agent play support.
. DAPI: verify SQL transaction isolation, CAS implementation, additive migrations, durable `ctx.emit` and periodic jobs in the actual target runtime; clarify same-runtime `ctx.call` vs authenticated remote HTTPS.
. Social: implement or verify ticket issuance and introspection/JWKS contract, revocation and scoped account-to-seat grants; design idempotent notification intake.
. Atrium: discover only reviewed `looprd.game-play/v1` game capabilities, provide account-bound launch/resume, do not infer that metadata allows agent play.
. All: share interoperability fixtures, simulated faults and owner-signed test evidence. The proposal is not a deployed protocol.

== Blocking decisions requiring owners

* Approved Node evaluator isolation/runtime and old-engine artifact retention.
* Social issuer / remote trust / grant revocation format.
* Whether trusted-private client receipt is permitted temporarily, and its limitations.
* Overdue-turn policy beyond `mark_overdue`/remind.
* SQL dialect, transaction and durable event semantics in deployed DAPI.

== Acceptance sequence

. LIFE-ASYNC-01: 100+ seeded campaigns; browser and Node replay with explicit AI and no-load side effects. Current v0.5.80 is a partial foundation only.
. LIFE-ASYNC-02: additive SQL schema, checksums, restarts, snapshots and action journal.
. LIFE-ASYNC-03: verified identity, membership, CAS, idempotency, bounded actions, migration bridge.
. LIFE-ASYNC-04: trusted command-only evaluator + agent legal-actions flow.
. LIFE-ASYNC-05: 60-hour overdue / unlimited deadline, transactional outbox, Social recovery.
. LIFE-ASYNC-06: Atrium resume + Tavi notification + browser-off OpenClaw acceptance.

Do not remove `/session` or require login for standalone `PLAY.html`. Never replace existing game saves in place, never delete active matches due to elapsed TTL, and do not claim any deployment until verified.

== v0.5.81 implementation delta

* Added five *inert* game-owned LoopRD models under schema version 3: `GameMatch`, `GameParticipant`, `GameAction`, `GameCheckpoint`, `GameNotificationOutbox`.
* Legacy `Room` storage, `/session` handler and 48-hour legacy room TTL are unchanged; new matches must not use the legacy TTL.
* The new models are not yet proof of restart-safe lifecycle, verified identity, composite uniqueness constraints, transactional CAS, Social event dispatch or server-evaluated `/play`. Those remain hard P0 blockers for deployment.
* Migration to a running SQLite/PostgreSQL LoopRD environment requires a backup, dialect/index validation, and a real restart test; none were performed by this source package.
