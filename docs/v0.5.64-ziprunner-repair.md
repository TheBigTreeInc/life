# v0.5.64 ZipRunner compatibility repair

## Root cause

ZipRunner ran `node tools/verify.mjs` in an existing local project. The local `tests/language-campaign.test.cjs` was not shipped in any of the v0.5.56–v0.5.64 release ZIPs; the reported test expects `id="languageSelect"` in the static game HTML. The actual setup UI had only `id="gameLanguage"` in the dynamically rendered New Game modal. The release ZIP package manifest identifies version `0.5.64`; ZipRunner's detected `0.5.58` is likely its previously successful local state, not the supplied package's version.

## Source-only compatibility fix

- Add a keyboard-accessible main-toolbar `languageSelect` dropdown to `index.html`, with EN and NL options.
- Synchronize it with the existing New Game `gameLanguage` dropdown through `LifePass057.saveLocale` and the existing `the-life-loop-language-v1` preference. Update the document language.
- Preserve existing source tests; add `tests/language-compat-064.test.cjs` to catch both normal and offline HTML drift.
- Regenerate `PLAY.html` and Pages from source. No Classic gameplay or saved-game schema change.

## Operator checks

1. Apply this full-source repair ZIP through ZipRunner as a source overlay, preserving private config and local state. Do not delete any local tests or private settings.
2. Run `node tools/verify.mjs` on the **actual merged project folder**. Both shipped and locally retained test files must pass. If it fails, capture the **first failing test name and assertion** from the untruncated log.
3. Open `PLAY.html` or the local server, switch the toolbar between EN and NL, open New Game → Game settings and verify both language selectors agree. Reload and verify the selection persisted.
4. Confirm Classic still starts at zero happiness, 25 relaxation, $200 cash and no pantry food.

The feature remains a partial English/Dutch **setup/localization foundation**, not complete gameplay translation. No Git push or deployment was performed.
