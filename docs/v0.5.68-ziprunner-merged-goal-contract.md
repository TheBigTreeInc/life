# v0.5.68 — Retained ZipRunner goal-preset contract

**Status:** Source implemented and release-gated; operator merged-tree acceptance outstanding.

## Origin

The Windows ZipRunner merge of the new `0.5.67` source preserved an older local-only `tests/language-campaign.test.cjs` which asserts the JavaScript source calls `GoalPresets.goals(key)`. The release shipped `UX57.presetGoals(...)` and therefore failed before gameplay was tested. That local test file has **not** been provided, and other assertions in it remain unknown.

## Implementation

- New `src/goal-presets.js` exposes `window.GoalPresets` and `window.LifeGoalPresets`, with CommonJS export for regression tests.
- `GoalPresets.goals(key)` validates `quick`, `standard` or `extended` and delegates to the canonical `LifePass057.presetGoals` values, giving four equal targets and preventing duplicate preset tables.
- `GoalPresets.detect(goals)` synchronizes manual slider changes with the current selector. `custom` does not overwrite player-specified slider values.
- New Game calls `GoalPresets.goals(key)` with the selected preset; the normal page and standalone PLAY.html load the module before `src/app.js`.
- No changes to the four victory goal formulas, the 60-unit DOS clock, Modern balance, serialization, multiplayer, or house rules.

## Merged-tree acceptance

Run `node tools/verify.mjs` in ZipRunner's **merged** project and capture the first failed assertion from any local-only test. The release now packages cumulative browser entrypoint checks for `languageSelect`, `I18n.set`, `campaignPreset`, and `GoalPresets.goals(key)`. It cannot prove all expectations from a local test not supplied with the project release. Do not delete local tests or local/private config to make the build pass.

## Release discipline

Always increment the numeric version for changed source archives. `0.5.68` supersedes `0.5.67`; both release names and handoff metadata are distinct. No automatic Git push or deployment.
