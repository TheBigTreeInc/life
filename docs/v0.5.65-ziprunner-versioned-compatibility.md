# v0.5.65 — Versioned ZipRunner compatibility release

**Status:** Implemented, pending Windows merged-tree operator acceptance.

## Why this build

The v0.5.64 repair was distributed under the same numeric version as a failing ZIP, violating ZipRunner's version-based release identity. This new build uses **v0.5.65**, with a single authoritative version across all source/release metadata. The game fix itself is the already implemented working EN/NL language toolbar `languageSelect` synchronized with the existing New Game language preferences.

## Immutable release discipline

1. Any source correction, including a hotfix, must use a strictly higher numeric major.minor.patch version than the previous distributed artifact; never redistribute different contents under the same release number.
2. Keep `package.json`, `ZIPRUNNER_HANDOFF.txt`, `.ziprunner-workboard-update.json`, `looprd.yaml`, `docs/parity-contract.json`, workboard classification, artwork/portrait manifests, index footer and generated `PLAY.html` synchronized.
3. Maintain `docs/release-ledger.json` so the current version is a new final ledger entry with an explicitly recorded predecessor. The full-source packager must include this ledger and all shipped JavaScript test files.
4. Treat tests retained in the operator's local ZipRunner project as part of its merge; only a run against that merged tree can validate all local-only tests. Never delete local tests to make a release pass.
5. Do not include `.git`, `.env`, local/private config, generated dist, runtime saves or credentials. GitHub push and deployment remain operator-controlled.

## Operator acceptance

Import `the-life-loop-0.5.65-ziprunner.zip` through ZipRunner. Verify it reports version **0.5.65**; run `node tools/verify.mjs` in the merged target folder. Check toolbar EN/NL selection, New Game settings and persistence. Check a new Classic game retains DOS opening state (happiness 0, relaxation 25, cash $200, no pantry food), and load an existing saved game. If a local-only test fails, provide the first failing assertion from the new job log.

**Scope:** version and integration hotfix only; next DOS runtime comparison moves to **v0.5.66**.
